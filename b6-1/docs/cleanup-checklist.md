# 리소스 정리 체크리스트

리전: ap-northeast-2 (서울) / 대상 VPC: mission-vpc (`10.0.0.0/16`)

---

## 정리 전 확인

- [ ] 제출용 스크린샷을 모두 확보했다 (삭제 후에는 재촬영 불가)
- [ ] 다이어그램·보고서에 기재할 리소스 ID를 모두 옮겨 적었다
- [ ] 퍼블릭 IP, 인스턴스 ID 등 문서에 들어갈 값을 README에 반영했다

---

## 삭제 순서

의존 관계의 **역순**으로 지운다. AWS는 다른 리소스가 참조 중인 대상의 삭제를 거부하므로, 순서를 지키지 않으면 "종속 항목이 존재합니다" 오류가 발생한다. 과금이 큰 항목이 앞쪽에 오도록 배치했다.

### 1. EC2 인스턴스 — **과금 최대**

- [ ] 인스턴스 선택 → 인스턴스 상태 → **종료(Terminate)**
- [ ] 상태가 `terminated`로 바뀐 것을 확인

> **중지(Stop)가 아니라 종료(Terminate)여야 한다.** 중지하면 인스턴스 시간당 요금은 멈추지만 EBS 볼륨 요금은 계속 발생한다. 종료해야 과금이 완전히 끊긴다.

### 2. EBS 볼륨

- [ ] Elastic Block Store → 볼륨 목록 확인
- [ ] 인스턴스 종료 시 함께 삭제되었는지 확인 (`available` 상태로 남은 볼륨이 있으면 수동 삭제)

> 기본 설정에서는 루트 볼륨이 인스턴스와 함께 삭제된다. 다만 "종료 시 삭제" 옵션을 해제했거나 추가 볼륨을 붙였다면 고아 볼륨이 남아 계속 과금된다. 눈에 띄지 않아 방치되기 쉬운 항목이다.

### 3. 스냅샷

- [ ] 생성한 스냅샷이 있는지 확인 후 삭제

### 4. Elastic IP

- [ ] 탄력적 IP 목록 확인 → 있다면 **연결 해제 후 릴리스**

> 이번 실습에서는 사용하지 않았다(자동 할당 퍼블릭 IP 사용). Elastic IP는 **인스턴스에 연결되지 않은 상태일 때 오히려 과금**되므로, 인스턴스만 지우고 IP를 방치하면 요금이 계속 발생한다.

### 5. 키 페어 (선택)

- [ ] `mission-key` 삭제 여부 결정

> 과금되지 않는다. 재실습 계획이 있으면 유지해도 무방하다. 로컬의 `.pem` 파일도 함께 정리한다.

### 6. Security Group

- [ ] `mission-web-sg` 삭제

> 인스턴스가 완전히 종료된 뒤에만 삭제된다. `terminated` 상태로 바뀌고도 잠시 참조가 남아 있을 수 있으니, 실패하면 몇 분 뒤 재시도한다. Default VPC의 기본 보안 그룹은 건드리지 않는다.

### 7. 서브넷

- [ ] `mission-public-subnet` 삭제

### 8. 라우팅 테이블

- [ ] `mission-public-rt` 삭제

> 메인 라우팅 테이블은 개별 삭제되지 않으며 VPC 삭제 시 함께 사라진다.

### 9. Internet Gateway

- [ ] VPC에서 **분리(Detach)**
- [ ] IGW **삭제**

> 분리와 삭제는 별개 작업이다. 분리하지 않으면 삭제할 수 없다.

### 10. VPC

- [ ] `mission-vpc` 삭제
- [ ] **Default VPC(`172.31.0.0/16`)는 삭제하지 않는다**

> VPC 자체는 과금 대상이 아니지만, 정리 완료를 명확히 하기 위해 삭제한다. 콘솔에서 VPC를 삭제하면 남아 있는 종속 리소스를 함께 정리해준다.

### 11. IAM 사용자 (선택)

- [ ] `cody-iam` 유지 여부 결정

> 과금되지 않는다. 다만 사용하지 않는 자격 증명을 방치하는 것은 보안상 바람직하지 않다. 재실습 계획이 없다면 콘솔 액세스를 비활성화하거나 사용자를 삭제한다.

## 정리 후 검증

- [ ] EC2 대시보드 리소스 패널에서 인스턴스·볼륨·보안 그룹 수가 0 또는 기본값인지 확인
- [ ] VPC 콘솔에 Default VPC만 남아 있는지 확인
- [ ] Billing → 청구서에서 당월 예상 요금 확인
- [ ] 증빙 스크린샷 저장 (`docs/images/06-cleanup-billing.png`)

> Billing 정보는 기본적으로 루트 계정에서만 조회된다. IAM 사용자로는 접근 거부가 뜨는 것이 정상이므로 이 확인은 루트 계정으로 수행한다.

## 과금 발생 요인 정리

| 리소스 | 과금 여부 | 비고 |
| --- | --- | --- |
| EC2 인스턴스 | 시간당 | 실행 중일 때만. 중지 시 인스턴스 요금은 정지 |
| EBS 볼륨 | 시간당 | **인스턴스를 중지해도 계속 발생** |
| 퍼블릭 IPv4 주소 | 시간당 | 자동 할당 IP 포함 |
| Elastic IP | 시간당 | **미연결 상태에서 과금** |
| 스냅샷 | 용량당 | |
| 데이터 전송(아웃바운드) | 전송량당 | 실습 규모에서는 미미 |
| VPC / 서브넷 / IGW / 라우팅 테이블 | 없음 | |
| Security Group / IAM | 없음 | |

**핵심**: 요금은 "만들어둔 것"이 아니라 "켜져 있는 것"과 "저장 공간을 점유하는 것"에서 발생한다. 네트워크 구성요소는 무료이고, 실제 비용은 EC2·EBS·퍼블릭 IP에 집중된다. 실습 후 요금이 새는 대부분의 사례는 인스턴스를 중지만 하고 볼륨을 방치했거나, Elastic IP를 릴리스하지 않은 경우다.

## 예방 조치 (권장)

- [ ] Billing → Budgets에서 예산 알림 설정 (예: $5 초과 시 이메일)

> 예산 알림 자체는 무료다. 실습 종료 후 의도치 않게 남은 리소스가 있어도 며칠 내에 알아챌 수 있다.
